# 🔧 MakeKeeper — Анализ нового функционала

## Что уже реализовано (текущий MVP)

| Модуль | Что есть |
|--------|----------|
| **Projects** | Список проектов, статусы (IDEA→COMPLETED), задачи, привязка компонентов, AI-чат |
| **Inventory** | Склад деталей, SKU, категории, минимальный остаток, ссылка на даташит |
| **Logistics** | Заказы (CART→DELIVERED), трек-номер, авто-список покупок, оприходование |

## 🗂️ Группа 1 — Углубление управления проектами

### 1.1 Временные рамки и Gantt-планирование
**Проблема:** задачи имеют `dueDate`, но нет визуального представления сроков.  
**Решение:**
- Интерактивная Gantt-диаграмма на основе задач проекта
- Drag-and-drop переназначение дат
- Критический путь (выделение задач, которые задерживают финиш)
- Автоматический расчёт % завершённости проекта по задачам

**БД:** добавить в `Task` поля `startDate`, `estimatedHours`, `actualHours`

---

### 1.2 Шаблоны проектов
**Проблема:** каждый новый проект создаётся с нуля.  
**Решение:**
- Библиотека шаблонов (Arduino Starter, ESP32 Weather Station, 3D Printer Mod)
- Сохранение любого проекта как шаблон
- Импорт шаблона с автоматическим созданием задач + списка компонентов

**БД:** новая модель `ProjectTemplate { id, name, tasksJson, componentsJson }`

---

### 1.3 Теги и категоризация проектов
**Проблема:** при большом числе проектов нет гибкой фильтрации.  
**Решение:**
- Теги (`#arduino`, `#esp32`, `#3d-printing`, `#woodworking`)
- Фильтр + поиск по тегам
- Статистика по тегам (сколько проектов в каждой категории)

**БД:** `ProjectTag { id, name, color }`, `ProjectTagLink { projectId, tagId }`

---

### 1.4 Журнал изменений / Activity Log
**Проблема:** нет истории «кто что и когда делал» (важно при возобновлении проекта через месяцы).  
**Решение:**
- Автоматическая запись событий: создана задача, изменён статус, добавлен компонент, создан заказ
- Timeline на дашборде проекта
- Возможность добавить ручную заметку в лог (дневник разработчика)

**БД:** `ActivityLog { id, projectId, eventType, payload JSON, createdAt }`

---

### 1.5 Подзадачи и дерево задач
**Проблема:** сложные задачи невозможно декомпозировать.  
**Решение:**
- Иерархия задач: задача → подзадача (1 уровень вложенности)
- Коллапсируемые группы задач
- Автоматическая отметка родительской задачи, когда все подзадачи выполнены

**БД:** добавить в `Task` поле `parentTaskId String?`

## 📦 Группа 2 — Продвинутый инвентарь

### 2.1 Штрих-код и QR-код для компонентов
**Проблема:** физический поиск деталей в ящиках — ручной и медленный процесс.  
**Решение:**
- Генерация QR-кода для каждого компонента (с названием, ячейкой, SKU)
- Сканирование камерой смартфона → открытие карточки компонента
- Печать этикетки (PDF с QR) для наклейки на ящик

**Библиотеки:** `qrcode` (backend, уже стабильная), `jsQR` или камера браузера (WebRTC)

---

### 2.2 История движения склада (Stock Movements)
**Проблема:** нет истории — непонятно, откуда взялось и куда ушло количество.  
**Решение:**
- Лог всех операций прихода/расхода
- Типы операций: `PURCHASE` (заказ), `RESERVED` (резерв под проект), `USED` (списано), `ADJUSTMENT` (ручная корректировка), `RETURN`
- График остатков по времени (sparkline)

**БД:** `StockMovement { id, componentId, delta Int, type, orderId?, projectId?, note?, createdAt }`

---

### 2.3 Поставщики и прайс-листы
**Проблема:** нет структурированного хранения информации о магазинах и ценах.  
**Решение:**
- Справочник поставщиков (AliExpress, LCSC, Mouser, DigiKey, локальные)
- Привязка цены компонента к конкретному поставщику
- Сравнение цен на одну деталь у разных поставщиков
- Автоматическое добавление лучшего поставщика в заказ

**БД:** `Supplier { id, name, url, country }`, `ComponentPrice { id, componentId, supplierId, price, currency, updatedAt }`

---

### 2.4 Виртуальные «Ящики и Полки» (Storage Map)
**Проблема:** поле `location` — просто строка, нет структуры.  
**Решение:**
- Иерархическая система хранения: `Шкаф > Полка > Ящик > Ячейка`
- Визуальная карта склада (drag-and-drop размещение)
- Быстрый поиск детали → «Деталь находится в Ящике A3, полка 2»
- Предупреждение при конфликте ячеек (два компонента в одной)

**БД:** `StorageLocation { id, parentId?, name, level (CABINET/SHELF/BOX/CELL) }`

---

### 2.5 Категории и атрибутные схемы
**Проблема:** `category` — просто строка, у разных типов деталей разные атрибуты.  
**Решение:**
- Категории с иконками (Resistors, Capacitors, MCUs, Sensors, Connectors...)
- Для каждой категории — своя схема атрибутов (для резистора: `resistance`, `tolerance`, `power`; для конденсатора: `capacitance`, `voltage`, `type`)
- Фильтр по атрибутам (найти все резисторы 10кОм ±1%)

**БД:** `ComponentCategory { id, name, icon, attributeSchema JSON }`, добавить `categoryId` в `Component`

---

## 🚚 Группа 3 — Логистика и закупки

### 3.1 Бюджет проекта
**Проблема:** нет учёта расходов на проект целиком.  
**Решение:**
- Бюджет проекта: плановый vs. фактический
- Автоматическое суммирование стоимости заказанных компонентов
- Диаграмма расходов по проекту
- Предупреждение при превышении бюджета

**БД:** добавить в `Project` поля `budgetPlanned Float?`, `budgetCurrency String?`

---

### 3.2 Авто-трекинг посылок (Parcel Tracking API)
**Проблема:** статус посылки обновляется вручную.  
**Решение:**
- Интеграция с 17track.net или TrackingMore API
- Автоматический опрос статуса каждые 6 часов (cron-job)
- Push-уведомление (браузерное) при изменении статуса
- История трек-событий с таймлайном

**БД:** `TrackingEvent { id, orderId, status, location, eventTime, raw JSON }`

---

### 3.3 Умный список покупок
**Проблема:** текущий shopping-list показывает только дефицит, без группировки и приоритетов.  
**Решение:**
- Группировка дефицитных компонентов по предпочтительному поставщику
- Автоформирование «корзины» для каждого магазина
- Экспорт списка в CSV / копирование в буфер
- «Умные» предложения: если компонент есть у 3 поставщиков — показать самый дешёвый

---

### 3.4 Возвраты и рекламации
**Проблема:** нет учёта бракованных деталей.  
**Решение:**
- Отметить компонент из заказа как «бракованный»
- Создать Return Request с трек-номером возврата
- Статусы возврата: `INITIATED` → `SHIPPED_BACK` → `REFUND_RECEIVED`
- Автоматическое списание с инвентаря

## 🤖 Группа 4 — AI и автоматизация

### 4.1 AI Copilot с памятью проекта (расширение)
**Проблема:** AI-чат не имеет «памяти» между сессиями и не использует весь контекст.  
**Решение:**
- Полный System Prompt: статус проекта + задачи + список компонентов + история заказов
- Сохранение сессий — продолжение разговора при следующем открытии
- AI «проактивно» предлагает действия: «Вы заказали ESP32, хотите добавить задачу "Настроить среду разработки"?»
- Переключение режимов: 💬 Chat / 🔎 Research (поиск компонентов) / 🛠️ Plan (генерация плана проекта)

---

### 4.2 AI Парсинг датащитов (PDF → Component Card)
**Проблема:** пользователь вручную вводит характеристики компонентов.  
**Решение:**
- Загрузка PDF-даташита на карточку компонента
- AI извлекает: напряжение питания, токи, распиновку, корпус, описание
- Автозаполнение полей `customFields`
- Создание структурированного `pinout JSON` для раздела «Схемы»

---

### 4.3 AI Генерация плана проекта
**Проблема:** пустой проект без задач — разработчик тратит время на планирование.  
**Решение:**
- Форма: «Хочу создать умную теплицу на ESP32 с датчиком влажности и капельным поливом»
- AI генерирует: список задач с оценкой времени + список необходимых компонентов
- Один клик → создать проект с этими задачами и добавить компоненты в shopping list

---

### 4.4 Схемы и распиновка (Pinout Board)
*Уже в ROADMAP — детализация:*
- SVG-рендер плат (ESP32, Arduino, STM32, Raspberry Pi)
- Цветовая маркировка пинов по функции (PWM/ADC/I2C/SPI/UART/Power/GND)
- Таблица связей «Компонент → Пин платы»
- Автоматическая проверка: конфликты пинов, уровни напряжения
- Экспорт схемы в SVG/PNG

---

### 4.5 AI Code Generator + Monaco Editor
*Уже в ROADMAP — детализация:*
- Генерация шаблона прошивки на основе схемы пинов
- Поддержка: Arduino C++, MicroPython, ESP-IDF
- Monaco Editor в браузере (WebWorker, без сервера)
- AI Debugger: вставить ошибку компилятора → получить исправление
- История версий кода с diff-просмотром

## 📊 Группа 5 — Аналитика и дашборд

### 5.1 Главный дашборд (Home Overview)
**Проблема:** сейчас `HomeView.vue` — список проектов без аналитики.  
**Решение:**
- Карточки: «Активных проектов», «Деталей на складе», «Заказов в пути», «Потрачено за месяц»
- График активности (commits-style heatmap по дням)
- Список: «Ближайшие дедлайны задач»
- Список: «Детали на исходе» (quantity < minQuantity)
- «Недавняя активность» (последние 10 событий из ActivityLog)

---

### 5.2 Отчёты и экспорт
**Проблема:** нет возможности получить данные вне приложения.  
**Решение:**
- Экспорт инвентаря в CSV/Excel
- Экспорт истории заказов в PDF (отчёт для налогов/бухгалтерии)
- Экспорт плана задач проекта в PDF (спецификация)
- Экспорт BOM (Bill of Materials) проекта в стандартный формат CSV

---

### 5.3 Статистика инвентаря
- Общая стоимость склада по текущим ценам
- ТОП-10 самых дорогих компонентов
- Компоненты, не используемые ни в одном проекте («мёртвый сток»)
- Оборачиваемость: как часто компонент используется и докупается
